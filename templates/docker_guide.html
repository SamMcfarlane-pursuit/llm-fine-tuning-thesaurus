Docker Guide for LLM Fine-Tuning

Learn how to use Docker to containerize and deploy your fine-tuned language models

Introduction to Docker for ML

Docker is a powerful tool for creating, deploying, and running applications in containers. For machine learning and specifically LLM fine-tuning, Docker provides several key benefits:

Environment Consistency

Docker ensures that your fine-tuning environment is consistent across development, testing, and production. This eliminates "it works on my machine" problems and makes your work reproducible.

GPU Support

Docker can leverage GPU acceleration for training and inference, making it ideal for resource-intensive LLM fine-tuning tasks.

Portability

Package your fine-tuned models with all dependencies and share them with others or deploy them to any environment that supports Docker.

Scalability

Easily scale your fine-tuning or inference workloads using container orchestration tools like Kubernetes.

Docker Basics for ML Engineers

Key Docker Concepts

Concept Description
Container A lightweight, standalone, executable package that includes everything needed to run an application.
Image A read-only template with instructions for creating a Docker container.
Dockerfile A text file with instructions to build a Docker image.
Volume Persistent data storage that exists outside the container lifecycle.
Docker Compose A tool for defining and running multi-container Docker applications.

Essential Docker Commands

# Build an image from a Dockerfile
docker build -t my-llm-image .

# Run a container from an image
docker run -p 8000:8000 my-llm-image

# Run with GPU support
docker run --gpus all -p 8000:8000 my-llm-image

# List running containers
docker ps

# Stop a container
docker stop container_id

# View container logs
docker logs container_id

# Execute a command in a running container
docker exec -it container_id bash

Docker for LLM Fine-Tuning

Creating a Dockerfile for Fine-Tuning

Here's a sample Dockerfile for LLM fine-tuning with PyTorch and Hugging Face Transformers:

# Use NVIDIA's PyTorch container as base image
FROM nvcr.io/nvidia/pytorch:23.04-py3

# Set working directory
WORKDIR /app

# Install additional dependencies
RUN pip install --no-cache-dir \
    transformers \
    datasets \
    accelerate \
    bitsandbytes \
    peft \
    trl \
    wandb \
    tensorboard

# Copy fine-tuning code and configuration
COPY finetune_qlora.py .
COPY prepare_dataset.py .
COPY requirements.txt .
COPY run_finetuning.sh .

# Make the script executable
RUN chmod +x run_finetuning.sh

# Set the entrypoint
ENTRYPOINT ["/app/run_finetuning.sh"]
Best Practices
  • Use official base images from NVIDIA for GPU support
  • Pin specific versions of dependencies for reproducibility
  • Use multi-stage builds to reduce image size
  • Store large datasets and model checkpoints in volumes

Using Docker Compose for Fine-Tuning

Docker Compose allows you to define and run multi-container applications. Here's an example for LLM fine-tuning:

version: '3.8'

services:
  fine-tuning:
    build:
      context: .
      dockerfile: Dockerfile
    volumes:
      - ./data:/app/data
      - ./models:/app/models
    environment:
      - WANDB_API_KEY=${WANDB_API_KEY}
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
  
  tensorboard:
    image: tensorflow/tensorflow:latest
    command: tensorboard --logdir=/logs --bind_all
    volumes:
      - ./models:/logs
    ports:
      - "6006:6006"

Example 2: Deploying a Fine-Tuned Model with Docker

This example shows how to deploy a fine-tuned model as a REST API using FastAPI and Docker:

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel
import os

app = FastAPI(title="Fine-tuned LLM API")

# Model paths
BASE_MODEL_PATH = os.environ.get("BASE_MODEL_PATH", "distilgpt2")
ADAPTER_PATH = os.environ.get("ADAPTER_PATH", "./models/thesaurus-model-lora")

# Load model and tokenizer
@app.on_event("startup")
async def startup_event():
    global model, tokenizer
    
    print(f"Loading base model: {BASE_MODEL_PATH}")
    base_model = AutoModelForCausalLM.from_pretrained(
        BASE_MODEL_PATH,
        device_map="auto",
        torch_dtype=torch.float16
    )
    
    print(f"Loading adapter: {ADAPTER_PATH}")
    model = PeftModel.from_pretrained(base_model, ADAPTER_PATH)
    tokenizer = AutoTokenizer.from_pretrained(ADAPTER_PATH)
    
    print("Model loaded successfully!")

class GenerationRequest(BaseModel):
    prompt: str
    max_length: int = 100
    temperature: float = 0.7
    top_p: float = 0.9
    num_return_sequences: int = 1

class GenerationResponse(BaseModel):
    generated_text: str

@app.post("/generate", response_model=GenerationResponse)
async def generate_text(request: GenerationRequest):
    try:
        inputs = tokenizer(request.prompt, return_tensors="pt").to(model.device)
        
        with torch.no_grad():
            outputs = model.generate(
                inputs.input_ids,
                max_length=request.max_length,
                temperature=request.temperature,
                top_p=request.top_p,
                num_return_sequences=request.num_return_sequences,
                pad_token_id=tokenizer.eos_token_id
            )
        
        generated_text = tokenizer.decode(outputs[0], skip_special_tokens=True)
        return {"generated_text": generated_text}
    
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

@app.get("/health")
async def health_check():
    return {"status": "healthy"}

# Dockerfile.deploy
FROM nvcr.io/nvidia/pytorch:23.04-py3

WORKDIR /app

# Install dependencies
RUN pip install --no-cache-dir fastapi uvicorn peft transformers

# Copy application code
COPY app.py .

# Create directory for models
RUN mkdir -p /app/models

# Expose port
EXPOSE 8000

# Start the API server
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]

version: '3.8'

services:
  llm-api:
    build:
      context: .
      dockerfile: Dockerfile.deploy
    ports:
      - "8000:8000"
    volumes:
      - ./models:/app/models
    environment:
      - BASE_MODEL_PATH=distilgpt2
      - ADAPTER_PATH=/app/models/thesaurus-model-lora
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]

# Start the API container
docker-compose up -d

# Test the API with curl
curl -X POST http://localhost:8000/generate \
  -H "Content-Type: application/json" \
  -d '{"prompt": "A synonym for happy is", "max_length": 50}'

# Access the Swagger UI at http://localhost:8000/docs

# Stop the container when done
docker-compose down

Advanced Topics

Optimizing Docker Images for ML

  • Multi-stage builds: Use multiple stages to keep final images small.
  • Layer caching: Order Dockerfile commands to maximize cache usage.
  • Minimal dependencies: Only install what you need.
  • Non-root users: Run containers as non-root for security.

Distributed Training with Docker

  • Docker Swarm: Simple container orchestration for distributed training.
  • Kubernetes: Advanced orchestration for large-scale training.
  • Horovod: Distributed deep learning training framework.
  • DeepSpeed: Optimized distributed training for large models.

Integration with Hugging Face Hub

You can easily integrate your Docker-based fine-tuning with the Hugging Face Hub:

# Inside your Docker container
from huggingface_hub import login, push_to_hub

# Login to Hugging Face
login(token="your_huggingface_token")

# After fine-tuning, push your model to the Hub
model.push_to_hub("your-username/your-model-name")
tokenizer.push_to_hub("your-username/your-model-name")
Pro Tip

You can use Docker secrets or environment variables to securely store your Hugging Face token:

docker run -e HUGGINGFACE_TOKEN=${HUGGINGFACE_TOKEN} my-llm-image
